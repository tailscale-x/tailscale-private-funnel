# v3.3.1 — Keep reports fresh during external API stalls

## Fixed

- Accept authenticated runtime reports and health updates independently of DNS reconciliation, Tailscale endpoint discovery, and Service approval. Slow external APIs no longer hold the report-acceptance lock or consume healthy nodes' report leases.
- Give background reconciliation tasks independent, serialized workers and fresh timeout budgets.
- Resolve unchanged Docker application assignments without waiting behind Service provisioning. Reuse control-owned Kubernetes Service bindings on routine snapshots; ignore client-supplied Service targets.
- Recheck report and node freshness transactionally before stale-state removal, preserving reports renewed after a cleanup candidate scan.

WhoIs binding, signatures, replay rejection, revocation, exposure policy, and exact DNS ownership remain enforced. New DNS records or Service approvals can remain pending while their external APIs are unavailable. This correction does not provide availability during a control-database or Tailscale data-plane outage.

## Upgrade

Update the existing control image or binary in place, preserving its identity Secret, database, encryption/signing keys, and state. No reset, reenrollment, transfer, ACL changes, or manual DNS mutation is required. The correction is control-side; existing v3.3.0 load balancers and gateways can remain running.

## Verification

Both Go test suites, vet, PostgreSQL/SQLite expiry contracts, reproducible RPC generation, and embedded UI builds passed. The development build passed **340/340 public HTTPS checks during a 380.73-second stall of both Cloudflare and Tailscale management APIs**, with a maximum observed native report age of **29.55 seconds**. Checks covered the old admissions hosts, Kubernetes preview, Harbor, and Metube. All original node bindings, credentials, policies, and owned DNS ledger entries were retained.

See [report reconciliation](https://github.com/tailscale-x/tailscale-private-funnel/blob/v3.3.1/docs/report-reconciliation.md) and the [live verification record](https://github.com/tailscale-x/tailscale-private-funnel/blob/main/docs/verification/report-starvation-20261019.md) for fault scope, subsequent cluster interruptions, and released-artifact rollout results.

Artifacts include Linux amd64/arm64 and macOS arm64 binaries, checksums, release metadata, a multi-architecture GHCR image, standalone CRDs, and the OCI operator chart.
