# v3.1.0 — Installer-first provisioning and agent discovery

## Highlights

- Public native and Kubernetes `create` commands generate authorized installers. Execute the installer on the target host or a machine with the selected Kubernetes context; embedded tsnet connects before contacting private control.
- Bootstrap bundles are one-use and expire after 15 minutes. Credentials travel through stdin and are removed after initialization. Ordinary restarts preserve identity.
- Kubernetes installer generation requires no kubeconfig or cluster connectivity. Target-side checks validate the operator, permissions, resource conflicts, and Gateway API prerequisites.
- UI instructions use the same typed deployment contract and backend renderers as the CLI.
- Dynamic, authorized `/llms.txt` includes matching release binary downloads, checksum/install guidance, configured control URL, and management/native/Kubernetes CLI examples. Generated CLI and Connect API references remain linked from the same entrypoint.

## Breaking CLI change

`create` generates an installer; it no longer installs directly. `create-remote` and public bootstrap-consuming creation flags are removed. Run `--output script` to transfer an installer to its execution machine. Non-control generation requires authorized access to private control; execution targets need no pre-existing Tailscale installation.

## Downloads

Release assets include Linux amd64/arm64 and macOS arm64 binaries, `SHA256SUMS`, release metadata, and the OCI Helm chart archive. Verify the checksum before executing a binary. The container image packages those same prebuilt Linux binaries.

```sh
curl -fsSL https://raw.githubusercontent.com/tailscale-x/tailscale-private-funnel/v3.1.0/scripts/install.sh | sh -s -- --version v3.1.0
```

See [Installer workflow](https://github.com/tailscale-x/tailscale-private-funnel/blob/v3.1.0/docs/INSTALLER-WORKFLOW.md) and the [development rollout verification](https://github.com/tailscale-x/tailscale-private-funnel/blob/v3.1.0/docs/qa-development-installer-rollout.md). Real native and Kubernetes installer execution, cleanup, and public TLS recovery were verified with the preceding development artifact. Release artifact verification is separate from that deployment evidence.
