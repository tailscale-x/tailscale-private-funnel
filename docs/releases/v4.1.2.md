# v4.1.2

Fix unbounded idle control connections and add per-hostname Cloudflare proxy
configuration in Funnel Control.

## HTTP connection retention

Load-balancer polling now shares a bounded HTTP transport per connection owner,
instead of leaving a new transport and idle socket behind each poll. Embedded
and host-mode callers retain independent HTTP client options. Bound component
wrappers forward idle-connection cleanup, and closing an owner closes its idle
pool. Control closes idle HTTP connections after 90 seconds, including those from
older clients; active responses and streams are not subject to this idle budget.

The regression opens 200 connections before the fix and one after it for the same
200 polling calls. Live v4.1.1 evidence showed growing edge HTTP goroutines,
over 16,000 Control socket descriptors, and repeated historical Control OOM kills.
These findings establish the resource-retention defect, not attribution of every
byte of historical memory. Long-term memory acceptance remains a rollout check.
See [investigation](../verification/http-transport-retention-20261027.md).

## Hostname DNS mode

Administrators can choose DNS-only or Cloudflare proxy (orange cloud) in
**Exposures → Configure DNS**, or use the typed admin-only `SaveHostnameDNS` RPC.
The setting belongs to the hostname in Funnel Control and is shared by all routes
and gateways using it. Temporary HTTPRoutes and gateway reports cannot reset it.

New and existing hostnames default to DNS-only. No hostname is enabled for orange
cloud by upgrading. Cloudflare mode requires an enabled Cloudflare managed zone.
Exact DNS ownership checks still apply, updates patch the matching record IDs,
and failed proxy updates retain retryable record ownership. Stale edits are
rejected using a configuration revision. SQLite and PostgreSQL receive an
additive hostname-policy table migration.

Cloudflare Full (strict) TLS, certificate validation, upload limits and cache/WAF
behavior remain operational considerations. Zone SSL/TLS and cache settings are
not changed automatically. See [hostname DNS settings](../hostname-dns.md).

## Upgrade

Upgrade Control and every runtime component, including the public edge and
Kubernetes/native gateways. Existing identities, saved runtime configuration,
provider credentials and routing policies are preserved. No database restoration,
identity reenrollment or DNS ownership transfer is required. The additive schema
can remain if rolling binaries back; retain a pre-upgrade database backup.
