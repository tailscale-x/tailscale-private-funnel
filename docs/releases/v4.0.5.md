# v4.0.5 — Reliable reports and Service-host continuity

This patch consolidates the tested report-readiness and Service lifecycle fixes:

- Runtime reports use cancellation-aware, component-scoped serialization. Report snapshots, policy roles, nonces, and complete backend assignments commit atomically. Slow external reconciliation no longer blocks unrelated report acceptance.
- A retained load balancer can start its cached, component-bound routes while retrying transient control registration failures. Explicit authorization rejection still stops it; fresh installations require registration.
- Unchanged Service listeners remain open across configuration polls and backend changes. Existing connections retain their selected backend. Ordinary shutdown drains streams before final advertisement cleanup; revocation and lost assignment leases still fence immediately.
- Kubernetes forwarders first advertise only with reachable local Pods. Established hosts prefer local Pods and can use verified ready remote Pods for the same authorized backend during moves, with a bounded endpoint-gap grace. Arbitrary addresses and unrestricted ClusterIPs remain excluded.
- Generated role policies now include ICMP-only load-balancer access to this installation's gateway device roles. Live tests demonstrate that this prevents replacement Service hosts from being omitted from the existing edge's peer map. It grants no device TCP/UDP backend access. Funnel never applies policy edits automatically.
- Bounded storage/RPC timings and Service lifecycle events improve incident diagnosis without logging SQL arguments or credentials.

## Upgrade and operational boundary

Update control, load balancers, gateway agents and forwarders to the same patch. Preserve existing database/encryption material, native Tailscale state, Caddy certificate storage, and DNS ownership ledger. Kubernetes network instances remain disposable; logical component/application identities and ownership remain stable.

Merge the generated ICMP-only discovery grant into the existing installation policy after review. The live `main` installation already has the explicitly approved grant. No TCP 8766 health-channel rule, additional OAuth permission, or automatic ACL mutation is required.

Three isolated host replacements propagated in 3–4 seconds with complete streams. Three real DLKN forwarder replacements recovered without an edge restart or diagnostic-client join. Single-host applications still experience downtime while their sole eligible forwarder restarts; this patch does not promise zero-downtime host replacement or fix Tailscale's coordination service itself.

See [peer-discovery acceptance](https://github.com/tailscale-x/tailscale-private-funnel/blob/main/docs/verification/service-peer-discovery-20261020.md), [handoff tests](https://github.com/tailscale-x/tailscale-private-funnel/blob/main/docs/verification/service-handoff-20261020.md), and [report-readiness recovery](https://github.com/tailscale-x/tailscale-private-funnel/blob/main/docs/verification/report-readiness-recovery-20261020.md).

The unrelated foreground-tunnel development changes are not included in this patch.
