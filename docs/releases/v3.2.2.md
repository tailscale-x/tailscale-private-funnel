# v3.2.2 — Nested DNS record reconciliation fix

## Fixed

- Qualify nested provider-relative record names such as `api.tuyensinhhcmulaw` with their managed zone. Existing Cloudflare records now match desired records instead of triggering repeated `81058: An identical record already exists` errors.
- Preserve apex names, already-qualified names, explicit trailing-dot absolute names, and record data.
- Add regression tests for nested names and repeated, ownership-scoped reconciliation without duplicate writes. Unmanaged records still require explicit preview-bound approval; records owned by another node remain protected.

## Upgrade

Update control using the released binary. Ordinary updates preserve its database, Tailscale identity, encrypted credentials, enrollment state, and DNS ledger. No control transfer or reset is required. Gateway and load-balancer updates are not required for this control-side fix.

If earlier failures left provider records outside the ledger, review and approve those exact records through control's DNS preview/apply workflow. Do not delete records or bypass ownership protection.
