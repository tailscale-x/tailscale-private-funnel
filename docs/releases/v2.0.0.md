# v2.0.0 — Specialized gateways and Kubernetes installations

## Highlights

- Separate Docker, Tailnet, and Kubernetes gateways, with guided control UI provisioning.
- Public routing automatically reaches every eligible load balancer; users no longer select load-balancer IDs.
- Kubernetes Gateway API HTTPRoute and networking Ingress support, with validated timeout/body-limit annotations, namespace authorization, and Pod-backed endpoint validation.
- One controller/broker Deployment and a node-local forwarder DaemonSet per installation. Forwarders have independent persistent, lease-fenced Tailscale identities, no Kubernetes API permissions, and no remote-node fallback.
- Deploy control and load balancers with the same OCI Helm chart. Each uses one Recreate Deployment, a Secret-backed identity, and a retained PVC for SQLite or Caddy storage.
- Signed Kubernetes LoadBalancer Service discovery; pending or invalid addresses retain prior owned DNS. Real public client-IP preservation must be verified against the cluster's LoadBalancer implementation.
- Persistent reboot-safe identities, caller-scoped runtime APIs, WhoIs authorization, shared-tag policy, and exact ownership protection remain in place. Funnel never modifies Tailscale ACLs.

## Breaking changes and migration

`ingress` is removed. Use `docker-gateway`, `tailnet-gateway`, or `k8s-gateway`.
The combined-source and load-balancer selection contracts are removed; all runtime
clients and control must be upgraded together. Existing Docker-only records migrate
without changing identity. Direct tailnet exposures require a separately enrolled
Tailnet gateway and application Tailscale Service; do not assume an old load balancer
still forwards directly to a peer.

Stop the old process before transferring its identity. Back up control SQLite and its
matching encryption key/identity Secret. Kubernetes migrations from StatefulSets must
stop the old Pods before starting Recreate Deployments; do not run two processes with
one identity. Preserve controller and forwarder Secrets. Missing or corrupt state fails
startup instead of silently creating a new device.

See [operating instructions](../../PRIVATE_FUNNEL.md) and
[Kubernetes deployment, storage, migration, and rollback](../KUBERNETES.md).

## Helm and images

```sh
helm show chart oci://ghcr.io/tailscale-x/charts/tailscale-private-funnel --version 2.0.0
docker pull ghcr.io/tailscale-x/tailscale-private-funnel:v2.0.0
```

Use the control UI's generated commands for enrollment. Bootstrap credentials belong
in temporary Kubernetes Secrets, never Helm values. Back up identity Secrets and enable
cluster Secrets encryption at rest. Native Linux amd64/arm64 and macOS arm64 binaries,
checksums, the chart, and release metadata are attached. Metadata includes the immutable
image digest; the image publishes Linux amd64 and arm64.

## Verification and limits

Both Go suites, vet, generated UI assets, Helm contracts, native builds and the final
container are checked before release. Focused fixes cover per-match route precedence,
foreign-controller status preservation, WebSocket duplex bodies with backend timeouts,
and manual DNS retries using the signed Kubernetes Service address.

Final-image acceptance uses Pod replacement and real public HTTPS, forwarding-header
sanitization, streaming and WebSockets without rebooting any host. Existing Voice,
Flue, and Metube routes are checked, and disposable DNS is cleaned through control.
See [the release verification report](../qa-v2.0.0-release.md) for the exact evidence.

This is a supported HTTP subset, not a Gateway API conformance claim. Public TLS remains
Caddy-managed. Control and controllers are singletons; Recreate updates interrupt service.
Local storage and Secret backups remain necessary. Geographic affinity, uninterrupted
connections during host failure, HTTPS backends, and arbitrary Caddy snippets are not provided.

Helm rollback restores manifests, not database contents. A schema rollback requires a
compatible SQLite snapshot and its matching identity Secret. Never start the archived
native process while its Kubernetes replacement is running.
