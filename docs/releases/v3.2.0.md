# v3.2.0 — Identity-preserving control transfer and PostgreSQL

## Highlights

- `transfer-remote NAME native|k8s --source native|k8s --out FILE --yes` stops and fences control, durably saves its private installer, then removes owned source state without device revocation or DNS cleanup.
- Portable transfer preserves the complete Tailscale identity, signing/encryption keys, encrypted credentials, resource IDs, enrollments, reports and DNS ownership. Native/Kubernetes and SQLite/PostgreSQL destinations are supported.
- PostgreSQL joins SQLite as a supported control backend, with pgx, migration locking, encrypted credentials, database readiness and connection recovery. Control remains single-replica Recreate.
- Kubernetes control supports existing CloudNativePG connection/CA Secrets without a SQLite PVC. Referenced external database resources remain externally owned. Argo CD examples define the ownership and reconciliation boundaries.
- Operator suspension and transfer finalizers fence the source without ordinary revocation cleanup. Dependent component `controlRef` bindings become the same explicit management URL before source CR removal.
- Fresh control startup establishes its configuration signing key before readiness.

## Operator installation or upgrade

Run these commands from the machine with the target Kubernetes context. Replace `dlkn` for other clusters and explicitly list the installation namespaces the operator may manage. Apply CRDs before upgrading an existing operator; Helm does not update previously installed CRDs automatically.

```sh
kubectl --context dlkn apply --server-side --field-manager=funnel-crds \
  -f https://github.com/tailscale-x/tailscale-private-funnel/releases/download/v3.2.0/tailscale-private-funnel-crds.yaml

helm upgrade --install tailscale-private-funnel-k8s-operator \
  oci://ghcr.io/tailscale-x/charts/tailscale-private-funnel \
  --version 3.2.0 --kube-context dlkn \
  --namespace tailscale-private-funnel-k8s-operator-system --create-namespace \
  --set 'managedNamespaces[0]=tailscale-private-funnel-main-system' \
  --wait --timeout 5m
```

The chart defaults to the matching v3.2.0 runtime image. Gateway creation continues through the installer-generating `k8s gateways create` CLI, using this operator and an explicit target context/namespace. Install the pinned Gateway API CRDs before creating Kubernetes gateways, as documented in [Kubernetes deployment](https://github.com/tailscale-x/tailscale-private-funnel/blob/v3.2.0/docs/KUBERNETES.md).

## Transfer prerequisites and safety

Publishing this release does not upgrade or stop any existing deployment. A v3.1.0 native source must first be updated and started at v3.2.0; transfer enforces a matching source version. Upgrade the destination operator/CRDs and prepare its namespace/database references before generating the transfer installer.

For the existing native control named `main`, the subsequent operator-authorized source upgrade is:

```sh
sudo tailscale-private-funnel native controls update main --version v3.2.0 --wait
```

**Do not run transfer until ready for control downtime.** It stops the source immediately after preflight, preserves an owner-only installer before removing source state, and never automatically restarts the source after failure. Store the installer securely and execute it for one destination only. Stop GitOps reconciliation of source declarations before transferring Kubernetes control.

See [Control transfer](https://github.com/tailscale-x/tailscale-private-funnel/blob/v3.2.0/docs/CONTROL_TRANSFER.md), [PostgreSQL/CloudNativePG](https://github.com/tailscale-x/tailscale-private-funnel/blob/v3.2.0/docs/POSTGRESQL.md), and [local transfer verification](https://github.com/tailscale-x/tailscale-private-funnel/blob/v3.2.0/docs/verification/control-transfer.md). Seven disposable native/Kubernetes transfers preserved IPv4/IPv6 addresses and key hashes. SQLite/PostgreSQL contracts passed against PostgreSQL 16/18; existing public deployments were not migrated as part of that acceptance.
