# v3.2.4 — Correct parent Gateway publication status

## Fixed

- Aggregate published HTTPRoute hosts into their parent Gateway's `Programmed` condition. Host resource IDs identify routes, so direct comparisons against Gateway IDs previously left a working Gateway permanently pending.
- Resolve the actual parent namespace, listener section/port, hostname, and `allowedRoutes` permission before counting a host toward a Gateway's status. Unrelated Gateways remain pending.
- Add regression coverage for unpublished → published → withdrawn transitions and a second parent whose listener does not match the route hostname.

Includes v3.2.3's independent Service-approval and revoked-node cleanup loops, concurrency guard, and expired-context checks. Neither fix changes exposure policy, DNS ownership, ACLs, or authentication.

## Upgrade

Update control and the Kubernetes gateway image in their existing GitOps-managed component CRs to `ghcr.io/tailscale-x/tailscale-private-funnel:v3.2.4`. Keep identity Secrets, database references, broker state, and forwarder identity Secrets unchanged. The gateway controller needs the update for its corrected parent status; control needs v3.2.3 or later for independent Service approval.

Existing public load balancers do not require an update. Ordinary component updates retain identities and data; do not reset or transfer control.
