# v3.3.0 — Shared path-prefix routing and rewriting

## Added

- Kubernetes HTTPRoute `URLRewrite` with `ReplacePrefixMatch`, and the Ingress `tailscale-private-funnel.io/replace-prefix` annotation for explicit Prefix paths.
- Named Docker route labels under `tailscale-private-funnel.routes.<name>.` for hostname, port, path-prefix, and optional replace-prefix. Compact whole-host labels remain available as catch-alls.
- Shared, typed Caddy routing with segment-boundary matching, exact/longest-prefix precedence, suffix/query preservation, and internal prefix replacement. Gateways still forward raw TCP; no additional HTTP proxy or Tailscale identity is introduced.
- Multiple Docker paths on one hostname, separate backend assignments, signed route reports, hostname-scoped DNS ownership, and route details in the UI/API.

See [path routing](../path-routing.md) for Docker, Gateway API, and Ingress examples, supported behavior, and limitations. Rewrites do not change response bodies, redirect locations, or cookie paths.

## Fixed

- Create native binary version directories with explicit traversal permissions for the unprivileged runtime account, including installations launched with a private umask.
- Bound Caddy shutdown grace to five seconds so a long-lived request cannot indefinitely stall an update.
- Report node-identity database failures as temporary unavailability rather than revocation. Unknown, revoked, or mismatched identities remain denied.

## Upgrade

Update control and public load balancers before gateways. Use the existing deployment update operations or change the image in the existing component CR. Preserve identity Secrets, database configuration, state directories, Caddy certificate storage, and ownership ledger. No reset, transfer, schema migration, ACL change, or DNS overwrite approval is required.
