# v4.0.4 — Isolated hostname conflicts and safe Kubernetes retirement

A conflicting hostname no longer rejects an entire Kubernetes gateway snapshot. Unrelated routes continue reporting and programming; affected resources receive specific ownership diagnostics.

Explicit cleanup of a removed Kubernetes gateway now retires its exclusive registrations after owned DNS and unshared Service cleanup succeeds. Offline gateways do not release claims. Application history, exposure IDs, unrelated Services, and exact DNS ownership remain protected. Cleanup retries return recorded success and do not visit unrelated DNS zones.

Upgrade control and Kubernetes gateway agents together for resource-specific `Programmed` diagnostics. No identity reset, database migration, ACL change, or credential rotation is required.

Validation includes both Go suites, vet, SQLite and PostgreSQL 16/18 retirement contracts, generated-contract checks, live conflict isolation, Voice recovery, and public Facebook webhook verification. See [operational verification](https://github.com/tailscale-x/tailscale-private-funnel/blob/main/docs/verification/kubernetes-hostname-cleanup-20261020.md).

This patch does not claim to resolve the separate upstream Tailscale Service-host map delivery issue or cluster API availability problems.
