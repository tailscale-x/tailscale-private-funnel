## Policy-controlled routing across load balancers

- Exposures default to all eligible load balancers; select an explicit subset per public hostname when needed. Ingress enrollment no longer selects an edge.
- Public exposure DNS uses deduplicated A records for eligible load-balancer IPv4 addresses. Control converts matching owned CNAME records through reconciliation.
- Stable exposure IDs own DNS independently of ingress and load-balancer membership. Unowned records still require explicit preview-bound overwrite approval.
- Direct tailnet exposures connect from the load balancer to the verified backend device. Docker exposures retain their Tailscale Service and ingress path, with direct container forwarding rather than relay sidecars.
- Load balancers publish signed backend health and peer reports; policy, report freshness and connectivity govern route eligibility.

## Control UI and DNS management

- Edit, disable and delete exposure-policy rules, including multiple hostname regexes and revision checks.
- Manage multiple discovered domains per DNS provider. Credentials can be edited inline without replacing blank secrets.
- Resource display names are independent of immutable IDs. Zone ownership remains automatic and internal.
- Exposure details show per-edge policy, public-IP readiness and backend connectivity; enrollment and settings screens use clearer defaults.
- Verified Tailscale Owner/Admin roles authorize management; OAuth setup documents the required Users Read scope.

## Upgrade notes

Upgrade control, ingress and load-balancer binaries together: obsolete singular edge-assignment and relay contracts have been removed. Back up control SQLite data and its encryption key before upgrading. Database migrations preserve credentials, managed zones, reports and DNS ledger values; provider changes occur only through control reconciliation.

Existing exposures default to all load balancers, subject to policy and health. The prior owned gateway address is retained when endpoint discovery is ambiguous. Multiple A records provide distribution, not guaranteed client failover; DNS caching delays withdrawal.
