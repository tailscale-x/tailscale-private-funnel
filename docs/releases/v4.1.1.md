# v4.1.1

Foreground HTTP tunnels for Linux and Apple Silicon macOS, and independent
Kubernetes HTTPRoute lifecycle handling for shared hostnames.

## Temporary HTTPRoutes preserve existing applications

Adding or removing an exact challenge route on an existing hostname retains its
unchanged catch-all rules while the solver backend becomes ready or disappears.
Kubernetes backend probes cover every Service with bounded concurrency. New rules
wait for their own backend readiness; weighted rules require all positive-weight backends.
Pod discovery changes do not withdraw unchanged public rules. TCP listeners keep
one kernel accept queue across Caddy route reloads, preserving queued connections
instead of replacing sockets with `SO_REUSEPORT`. HTTP/3 retains its UDP mapping.

Programmed status now follows each resource generation and effective rule revision
installed and acknowledged by the edge. Rule precedence sorting preserves resource
ownership. A pending solver does not make a working Harbor route pending, and
merely sending a configuration does not count as installation.

See [investigation and regression coverage](../verification/temporary-httproute-lifecycle-20261023.md).
Live cert-manager staging issuance and renewal remain a separate acceptance step;
these tests do not establish zero downtime for arbitrary application replacements.

## Foreground local tunnels

Expose a loopback HTTP service with `tailscale-private-funnel tunnel PORT`.
The connected host phones home to private control for a 15-minute, single-use,
ephemeral Tailnet-gateway key. The command runs its own memory-backed Tailscale
identity and leaves the host's tags, device identity and Serve configuration alone.
Ctrl+C withdraws only that tunnel and queues owned DNS/Service cleanup.

The web UI includes **Expose a local port**, with backend-rendered commands,
connection-mode guidance, and readiness/cleanup explanations. Explicit host mode
remains available for an already role-tagged host.

Bootstrap issuance is limited to five requests per device and thirty requests per
installation per minute, including concurrent PostgreSQL callers. Counters persist
across control restarts and failed issuance counts against the budget.

See [foreground tunnel usage and verification limits](../foreground-tunnel.md).
The earlier real Mac acceptance is dated 19 October; current CI checks Darwin ARM64
portability, not fresh production-tailnet or public certificate issuance.

## Authorization and upgrade

Any verified Tailscale peer **allowed to reach control** may request foreground
bootstrap without a Funnel administrator role or host role tag. It receives this
installation's Tailnet-gateway runtime authority, not human management access.
Hostname policy, backend checks and exact DNS ownership still apply.

Generated policy templates permit tailnet peers to reach the control Service.
Existing policies are never changed automatically. Application-Service access
remains restricted to the installation load-balancer role. Both verified ICMP-only
peer-discovery grants from v4.0.7 remain present.

Upgrade control, load balancers and Kubernetes gateway agents together to obtain
per-resource publication status. Upgrade the CLI before using foreground tunnels.
Existing component identities, provider credentials, certificates and DNS ownership
remain intact. No database restore or identity migration is required.
