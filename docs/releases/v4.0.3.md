# v4.0.3 — Service-route continuity and bounded diagnostics

Add incident evidence for intermittent Tailscale Service routes without introducing
automatic identity resets or approval bypasses. This release does **not** claim to
fix all Service-map delivery/selection failures after host replacement.

## Diagnostics

- Log first dial failure, bounded periodic summaries and recovery, with target,
  error category, elapsed time and attempt count. Ignore canceled dual-stack racers.
- Sample only matching route metadata from the same running identity: device ID,
  advertised candidates and primary routes. No active probes run automatically.
- Log Service listener creation/withdrawal and reasons, plus forwarder assignment
  fencing/reacquisition with component and node identity context.
- Keep a private edge diagnostic socket for explicit dial/Disco-path inspection.
- Bound event rate, retained targets and background metadata reads. Credentials,
  raw netmaps and request contents are excluded.

## Continuity and consolidation

- Preserve previously ready routes and owned DNS during lost connectivity or
  negative health. Current policy, explicit removal and revocation still withdraw
  owned resources; new backends still require readiness.
- Start load balancers from their component-bound last successfully applied route
  cache before waiting for control. Authoritative empty configurations remain empty.
- Fence Kubernetes forwarding on assignment-lease loss while retaining the running
  tsnet identity, then reacquire only the unchanged binding. Pod replacement remains
  disposable. Separate broker availability from new-session registration readiness.
- Keep lease requests independent of slow configuration/provider operations; use
  distinct cold/warm configuration budgets and recheck expiry after slow fetches.
- Consolidate listener withdrawal under one synchronized path, preventing an old
  removal from deleting its replacement advertisement.
- Pin Tailscale SDK 1.102.4 for its peer-expiry delta correction (Go 1.26.6 minimum).
  Resolve tailnet DNS in the selected identity and commit once to its userspace
  route plan; missing routes cannot fall through to the host-network dialer.
- Preserve Caddy's configured connect timeout with the application-owned dialer.

## Upgrade and limits

Update control, load balancers and Kubernetes gateways in place to receive the
relevant diagnostics and continuity changes. Keep database/encryption material,
identity state and certificates. No reset, transfer, reenrollment, manual DNS
mutation, extra OAuth scope or ACL change is required. Publication does not update
running components automatically.

Native persisted identities remain persistent; Kubernetes identities remain
Pod-scoped/disposable. Existing runtime/API contracts are unchanged. Unrelated
foreground-tunnel work is not included in this patch.

Service selection/map delivery after host replacement and multi-backend readiness
summaries remain investigation gaps. A recovered TCP connection, passing probe or
Programmed condition is not a permanent-stability guarantee.

## Verification

Both Go suites, vet, targeted race tests, SQLite and PostgreSQL 16/18 contracts,
reproducible RPC/operator generation and UI assets, Helm lint and native image
startup were checked locally. The tag workflow additionally gates publication on
API-server contracts and publishes Linux amd64/arm64 and macOS arm64 binaries,
checksums, the multi-architecture image and OCI operator chart. Local checks do
not constitute new live public-routing acceptance; this release performs no rollout.
