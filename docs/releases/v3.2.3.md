# v3.2.3 — Keep Service approval progressing during DNS delays

## Fixed

- Reconcile Tailscale Service approval independently of DNS/provider maintenance, with a fresh timeout for each pass. Slow provider work can no longer exhaust the context before Service approval starts.
- Retry revoked-node cleanup independently so its provider/device operations cannot starve approval.
- Avoid queuing concurrent Service approval passes, stop processing expired contexts, and stop subsequent maintenance phases after their budget expires.
- Preserve existing WhoIs authorization, exact Service/device approval, DNS ownership, identity persistence, and report-expiry checks.

Regression tests block DNS and cleanup while verifying repeated Service approval with live contexts, reject canceled-context work, and prevent overlapping approval passes. This release also includes the nested DNS normalization fix from v3.2.2.

## Upgrade

Update the existing control image or binary in place; do not transfer, reset, or recreate control. Existing state, database bindings, credentials, identities, and DNS ownership remain in use. Gateways and load balancers do not require an update for this scheduling fix.

For operator-managed control, change `FunnelControl.spec.image` to `ghcr.io/tailscale-x/tailscale-private-funnel:v3.2.3` through the installation's GitOps source. Keep the identity Secret and database references unchanged. The existing Recreate strategy prevents concurrent control processes.
