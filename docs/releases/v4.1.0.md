## Foreground tunnels on Linux and Apple Silicon macOS

Expose a loopback HTTP service with `tailscale-private-funnel tunnel PORT`.
The connected host phones home to private control for a 15-minute, single-use,
ephemeral Tailnet-gateway key. The command runs its own memory-backed Tailscale
identity and leaves the host's tags, device identity and Serve configuration alone.
Ctrl+C withdraws only that tunnel and queues owned DNS/Service cleanup.

The web UI includes **Expose a local port**, with backend-rendered commands,
connection-mode guidance, and readiness/cleanup explanations. Explicit host mode
remains available for an already role-tagged host.

## Service transport

- Pin Tailscale SDK 1.102.4, including incremental peer-map fixes.
- Resolve tailnet Service names through the selected identity's LocalAPI DNS.
- Refuse host-network fallback for unknown or expired TailVIP routes.
- Preserve Caddy's connect timeout when using the process-owned Tailscale dialer.
- Keep dual-stack dialing, keep-alives, WebSockets and streaming.

## Authorization and upgrade

Any verified Tailscale peer **allowed to reach control** may request foreground
bootstrap; it does not need a Funnel administrator role or a host role tag.
The issued runtime role does not confer human management access. Hostname policy,
backend checks, report freshness and exact DNS ownership still apply. Issuance is
rate-limited per device and installation, with durable counters.

Generated policy templates now permit tailnet peers to reach the control Service.
Existing policies are never changed automatically. Application-Service access
remains restricted to the installation load-balancer role.

Upgrade control, load balancers and the CLI together before using the new command.
Existing component state, identities, provider credentials, certificates and DNS
ownership remain intact. Go 1.26.6 or newer is required for source builds.
