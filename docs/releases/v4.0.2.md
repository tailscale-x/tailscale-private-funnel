# v4.0.2 — Publish complete Cloudflare DNS names

Fix fresh-hostname NXDOMAIN responses caused by sending zone-relative owner names
to Cloudflare's create-record API. The pinned libdns client forwards these names
unchanged; the API requires complete names including the zone. Funnel now qualifies
names before appending, while preserving provider read normalization.

- Covers single-label, nested, complete, trailing-dot, and apex names.
- Preserves record data, targets, TTLs, exact-ID deletion, compensation, and DNS
  ownership checks. Other DNS vendors and runtime contracts are unchanged.
- Adds request-level regression tests exercising the real pinned client's HTTP
  serialization, plus A/CNAME/SRV/TXT data-preservation cases.

Development acceptance verified authoritative DNS, Cloudflare and Google public
resolution, and new Let's Encrypt certificates for three new hostnames across
both managed zones, including a nested hostname. Existing public routing and the
eleven-record ownership ledger remained intact. Both Go suites and vet passed.

See [diagnosis and verification](https://github.com/tailscale-x/tailscale-private-funnel/blob/main/docs/verification/cloudflare-complete-names-20261019.md).

The required deployment update is control only. Existing v4.0.1 load balancers,
gateways, and operators remain compatible. No database migration or identity reset
is required. Negative DNS caches created before the fix may persist until their
SOA-derived expiry; lowering an A record TTL does not clear them.
